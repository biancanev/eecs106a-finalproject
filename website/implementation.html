Implementation

Deep dive into our algorithms, sensor fusion, and control systems

System Architecture

Our system integrates multiple sensor modalities, state estimation filters, and control algorithms to achieve robust autonomous interception. The architecture features real-time sensor fusion, multi-modal perception, and optimal control with obstacle avoidance.

Perception & Sensing

Camera-Based Cone Detection: 6-Layer Heuristic System

We developed a sophisticated multi-layer filtering system for robust cone detection using HSV color segmentation. Each layer progressively filters candidates to eliminate false positives while maintaining high recall for actual cones.

Layer 1: HSV Color Detection

Initial color-based segmentation in HSV space provides robustness to lighting variations. Yellow cones use range [15-35, 80-255, 80-255] and blue target cones use [100-130, 120-255, 60-255]. HSV conversion naturally handles different illumination conditions better than RGB.

Layer 2: Convolution-Based Refinement

Morphological operations (erosion, dilation) clean up the binary mask, removing noise and filling gaps caused by reflections or shadows on cone surfaces.

Layer 3: Geometric Heuristics

Contour-based filtering rejects regions that don't match cone dimensions. Minimum area thresholds (200-300 pixels) eliminate small noise clusters. Aspect ratio checks ensure cones are taller than they are wide (ratio 0.8-5.0).

Layer 4: Triangular Shape Analysis

Polygonal approximation (Douglas-Peucker algorithm) identifies cone-like triangular shapes. We verify that the bottom width is at least 15% wider than the top, matching the physical cone geometry. Vertex count analysis (3-12 vertices) further validates shape consistency.

Layer 5: Solidity & Color Validation

Convex hull analysis ensures regions are at least 50% solid (not fragmented). Pixel sampling within regions validates that at least 30% of pixels match the target color, handling partial occlusions.

Layer 6: Position & Depth Validation

Ground-plane constraints: yellow cones must appear in the lower half of the image (cones sit on ground). Blue target cones are elevated ~10 cm, accounted for in depth estimation. Depth computed via pixel area: depth = √(fx × fy × CONE_AREA / pixel_count), with different area constants for yellow (0.021 m²) vs. blue target (0.146 m², 7× larger).

LIDAR Frame Auto-Calibration

Challenge: LIDAR mounting orientation is unknown—could be 0°, 90°, 180°, or 270° relative to robot forward direction. Manual calibration is error-prone and hardware-dependent.

Solution: Automated frame offset detection through multi-hypothesis testing and geometric consistency checking.

  • Algorithm: Test candidate offsets [0°, 90°, 180°, 270°] by extracting obstacles with each offset
  • Scoring: Compare LIDAR obstacle positions against fast local grid obstacles (ground truth from occupancy mapping)
  • Matching: Count obstacle matches within 30 cm threshold—correct offset yields highest match rate
  • Calibration: Collect 100 samples during normal operation, select offset with highest average score
  • Robustness: Works automatically without manual intervention, adapts to different LIDAR mounting configurations

This system eliminates the need for manual frame calibration and ensures consistent obstacle detection regardless of hardware setup variations.

Fast Local Occupancy Grid

High-frequency local map (5-10 Hz) for real-time obstacle awareness, complementary to Cartographer's slower global map (1-2 Hz).

  • Update Rate: Log-odds occupancy grid updated at LIDAR rate (5-10 Hz) vs. Cartographer's 1-2 Hz
  • Frame: Robot-centric coordinates, automatically transforms to world frame for MPC
  • Algorithm: Ray-casting with log-odds update: occupied cells += 0.8, free cells -= 0.6, clipped to [-3.0, 3.0]
  • Purpose: Provides immediate obstacle awareness for MPC planning, while Cartographer handles global consistency and loop closure

Multi-Modal Obstacle Detection

Fusion of multiple sensor sources with confidence-based weighting:

  • Fast Local Grid: 95% confidence (processed LIDAR, most reliable)
  • Raw LIDAR: 90% confidence (catches recent obstacles grid might miss)
  • Scan-Matched Points (Cartographer): 88% confidence (geometrically validated)
  • Camera Detections: 70-80% confidence (close range: 80%, far: 70%)

Fusion Strategy: Grid obstacles take priority. Camera detections refine LIDAR positions at close range (60% LIDAR distance + 40% camera angle). Duplicate obstacles within 20 cm are merged, keeping the higher-confidence or larger-radius version.

Target Detection & Tracking

Dual-Method Target Estimation

Method 1: LIDAR-Based Localization (Kabsch Algorithm)

Geometric alignment using Procrustes analysis (Kabsch algorithm) for optimal rigid body transformation between point sets.

  • Approach: Extract obstacles from target robot's local occupancy grid, match to seeker's global map
  • Algorithm: Kabsch algorithm computes optimal rotation and translation via SVD decomposition
  • Robustness: RANSAC-based outlier rejection handles noisy correspondences
  • Advantages: Accurate distance estimation, works when target is partially occluded
  • Limitations: Requires sufficient overlapping obstacles for alignment

Method 2: Camera-Based Detection

HSV filtering with depth estimation, accounting for target cone elevation (~10 cm above ground).

  • Approach: 6-layer heuristic system (same as obstacle detection) tuned for blue cones
  • Depth Estimation: Uses 7× larger area constant (0.146 m² vs 0.021 m²) for accurate depth
  • Elevation Handling: Target marker positioned at z=0.1 m in visualization and transforms
  • Advantages: Fast, works in any obstacle configuration, provides angular accuracy
  • Limitations: Depth less accurate than LIDAR, requires unobstructed view

Sensor Fusion Strategy

At close range (<1 m), camera provides accurate angular position while LIDAR provides accurate distance. Fusion combines 60% LIDAR distance + 40% camera angle for optimal pose estimate. Confidence scores guide fusion weights dynamically.

Unscented Kalman Filter (UKF) for Target Velocity Tracking

UKF tracks target velocity and position when detections are intermittent or noisy.

  • State Vector: [px, py, vx, vy] - position and velocity in 2D
  • Process Model: Constant velocity with process noise Q = 0.02 × I
  • Measurement Model: Position measurements with noise R = 0.03 × I
  • Sigma Points: 2n+1 = 9 points for n=4 state dimensions
  • Why UKF over EKF: Handles nonlinear dynamics better, no Jacobian computation needed, superior accuracy for target tracking

State Estimation

Extended Kalman Filter (EKF) for Robot Pose

High-rate sensor fusion (100 Hz) for smooth, accurate robot localization.

  • State Vector: [x, y, θ, vx, vy, ω] - position, heading, linear velocity, angular velocity
  • Sensor Fusion:
    • IMU gyroscope: angular velocity ω (R = 0.002)
    • IMU accelerometer: linear acceleration ax, ay (R = 0.4, gravity-compensated)
    • Magnetometer: heading θ (R = 0.02, auto-calibrated)
    • Odometry: position, heading, velocities (R = 0.01-0.05, lower weight due to wheel slip)
  • Process Model: Unicycle kinematics with process noise Q (position: 1e-4, heading: 5e-3, velocities: 0.01-0.02)
  • Update Rate: 100 Hz enables smooth control without lag
  • Why EKF over MCL: Deterministic, computationally efficient, multi-sensor fusion, absolute heading from magnetometer, real-time performance

Magnetometer Auto-Calibration: Collects 100 samples during initialization to compute offset, removing magnetic bias for accurate heading.

Covariance Expansion and Contraction in State Estimation

Proper management of covariance matrices is critical for accurate state estimation. Our filters implement careful expansion during prediction and contraction during measurement updates.

Covariance Expansion (Prediction Step)

During prediction, uncertainty increases as the system propagates forward with process noise:

  • EKF: P = F·P·Fᵀ + Q·dt where F is the Jacobian and Q is process noise
  • Process Noise (Q):
    • Position: 1e-4 (very small - robot motion is predictable)
    • Heading: 5e-3 (moderate - heading drift over time)
    • Linear velocity: 0.01 (higher - velocity can change quickly)
    • Angular velocity: 0.02 (highest - angular motion most uncertain)
  • Time-Dependent: Process noise scales with time step dt, ensuring covariance grows appropriately between updates

Covariance Contraction (Update Step)

During measurement updates, uncertainty decreases as new information reduces ambiguity:

  • EKF Update: P = (I - K·H)·P where K is Kalman gain and H is measurement matrix
  • Measurement Noise (R): Determines how much trust we place in measurements
    • IMU gyroscope: 0.002 (very low - highly accurate)
    • Magnetometer: 0.02 (low - provides absolute heading)
    • IMU accelerometer: 0.4 (high - noisy, requires gravity compensation)
    • Odometry position: 0.01 (moderate - subject to wheel slip)
  • Kalman Gain: K = P·Hᵀ·(H·P·Hᵀ + R)⁻¹ - automatically balances between prediction and measurement based on their relative uncertainties
  • Higher R: Less trust in measurement → smaller K → less covariance reduction
  • Lower R: More trust in measurement → larger K → more covariance reduction

Covariance Inflation for Safety (Target EKF)

For target estimation, we implement intentional covariance inflation when publishing to the seeker:

  • Scale Factor: 4.0× inflation of position and velocity covariances
  • Rationale: Conservative uncertainty prevents overconfidence in target position
  • MPC Safety: Larger uncertainty ellipses force MPC to plan more conservative trajectories
  • Implementation: Separate publishers: /target_estimate (true covariance) and /target_estimate_slow (inflated, throttled)
Inflated Covariance:
P_seeker = 4.0 × P_true

Numerical Stability and Bounding

To prevent numerical issues, we implement several safeguards:

  • Symmetry Enforcement: P = (P + Pᵀ) / 2 ensures covariance remains symmetric
  • Positive Definiteness: Small regularization term P += ε·I prevents singular matrices
  • Covariance Clipping: UKF bounds covariance elements to [-5.0, 5.0] to prevent explosion
  • Diagonal Bounds: Ensures diagonal elements (variances) remain positive and bounded
  • Joseph Form (UKF): More numerically stable covariance update: P = (I-KH)·P·(I-KH)ᵀ + K·R·Kᵀ

Key Insight: Covariance expansion during prediction reflects growing uncertainty over time, while contraction during updates reflects information gain. The balance between Q and R determines how quickly the filter trusts new measurements versus its predictions.

Target State Estimation with State Propagation

Robust target tracking with temporal smoothing and state propagation during occlusions.

  • Temporal Smoothing: Exponential moving average (α = 0.8) for position, filters noisy detections
  • Outlier Rejection: Rejects jumps >1.0 m from last estimate, prevents false updates
  • State Propagation: When target is occluded, propagates state forward using constant velocity model:
    • Position: x(t+dt) = x(t) + vx × dt
    • Confidence decays exponentially: confidence(t) = 0.9 × exp(-0.5 × dt)
    • Minimum confidence floor: 0.2 (never fully trust propagated state)
  • Final Approach: When <0.8 m from target, aggressive blending (α = 0.7) toward detections for precise interception

Control & Planning

Model Predictive Control (MPC)

Receding-horizon optimal control with obstacle avoidance constraints.

  • Horizon: 15 steps ahead (1.5 seconds at 10 Hz)
  • Time Step: dt = 0.1 s
  • State Space: Unicycle model [x, y, θ, v]
  • Control Inputs: Linear velocity v ∈ [0, 0.6] m/s, angular velocity ω ∈ [-1.5, 1.5] rad/s

Cost Function

  • Position Cost: Qp = 140.0 × ||p - p_target||² (strong goal attraction)
  • Heading Cost: Qθ = 25.0 × (θ - θ_ref)² (prefers straight paths, reduces curvature)
  • Control Costs: Ra = 0.01 × v², Rw = 0.15 × ω² (penalizes angular velocity strongly)
  • Obstacle Cost: Q_obs = 900.0 × smooth_penalty(distance) (avoids obstacles with high weight)
  • Terminal Cost: 10× position + 10× heading (strong terminal constraints)

Obstacle Avoidance

  • Constraint: Smooth penalty function for obstacles (no strict inequalities in CVXPY)
  • Safety Margin: Robot radius (0.105 m) + obstacle radius + 12 cm safety buffer
  • Trajectory Validation: Simulates entire predicted trajectory, checks clearance at each step
  • Velocity Scaling: Adaptive speed reduction near obstacles (0.5-1.0× based on minimum clearance)

Solver

  • Framework: CVXPY convex optimization
  • Solver: ECOS or OSQP (interior-point methods)
  • Fallback: Proportional control if MPC fails (angle error → ω, distance → v)

Waypoint Generation for Obstacle Navigation

When obstacles block the direct path, generates intermediate waypoints to thread through gaps.

  • Trigger: Obstacle within 0.25 m, directly ahead (±30° from forward direction)
  • Algorithm: Projects waypoint 25% toward goal, shifts laterally by minimum clearance needed
  • Clearance: obstacle_radius + robot_radius + 3 cm safety margin
  • Path Validation: Checks line-of-sight from robot to waypoint, ensures no obstacles intersect
  • Waypoint Clearing: Considers waypoint reached within 20 cm, cooldown prevents rapid waypoint switching

Terminal Guidance & Final Approach

Specialized behaviors for precise interception when close to target.

  • Activation: When distance to target < 0.8 m
  • Pose Locking: Aggressively locks to target position (α = 0.7 smoothing), prevents drift
  • Velocity Scaling: Reduces speed for precise approach (60-75% of maximum)
  • Final Approach Mode: MPC uses tighter constraints, prioritizes reaching target over obstacle avoidance
  • Goal Reached Detection: Within 15 cm of target position → mission complete

Emergency Recovery System

State machine for handling stuck or collision situations.

  • States: NORMAL → BACKUP → ROTATE → RECOVERY
  • Backup Phase: Reverses along known-safe trajectory history (1.5 seconds, 15 cm/s)
  • Rotate Phase: Spins up to 3 seconds to find clear path in any direction
  • Recovery: Resets waypoints and resumes normal operation
  • Trajectory Memory: Stores last 50 positions (5 seconds at 10 Hz) for safe backtracking

System Integration

ROS2 Node Architecture

  • ekf_pose_estimator: EKF sensor fusion (100 Hz pose updates)
  • cartographer_pose_bridge: Bridges Cartographer SLAM pose to /amcl_pose
  • fast_local_grid: High-speed local occupancy grid (5-10 Hz)
  • camera_cone_detector: 6-layer HSV filtering for cone detection
  • target_est_node: Multi-modal target estimation with state propagation
  • target_ekf_node: Camera-based target tracking (EKF)
  • ukf_node: UKF for target velocity tracking
  • mpc_node: Model Predictive Control with obstacle avoidance
  • trajectory_logger: Data logging for offline analysis

Data Flow & Synchronization

  • Sensor Rates: LIDAR (5-10 Hz), Camera (30 Hz), IMU (100+ Hz), Odometry (50 Hz)
  • Control Rate: MPC updates at 10 Hz (100 ms time step)
  • TF Transformations: All sensor data transformed to map frame for consistent coordinate system
  • Topic Latency: Typical end-to-end latency <200 ms (sensor → control)
